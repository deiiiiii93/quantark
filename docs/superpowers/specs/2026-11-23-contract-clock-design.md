# Contract clock: one rule for "the same instant" across products and engines

Status: owner decisions D1-D4 recorded 2026-11-23 ("A, b, confirmed"); awaiting
approval of this document. Nothing is built.

## 1. Intent

Every engine must price the same contract. Today each engine family decides
for itself whether two numeric event times are the same instant, with four
different rules, so the same booking can mean different contracts on different
engines. The owner's requirement: **schedule handling is consistent across
engines.**

How it surfaced (2026-11-23 lobe re-measure, `docs/bucket-futures-hedge/quad-readout/lobe_remeasure.py`):
a factory-built numeric KO-reset (`create_ko_reset_snowball(maturity_pre=1.0, maturity_post=1.5)`)
has schedule-1 time `11/12*1.0 = 0.9166666666666666` and schedule-2 time
`11/18*1.5 = 0.9166666666666667`, 1 ulp apart. QUAD V1, PDE and MC merge them
silently; QUAD V2 refuses with `NumericalError: QUAD V2 resource limit:
required 36559840344 nodes for minimum interior variance 6.9e-18`.

### Evidence

Engine rules today (each decides independently):

| consumer | where | "same instant" | in time units | representative |
|---|---|---|---|---|
| QUAD V1 (Snowball, Phoenix, KO-reset inherit) | `engine/quad/snowball_quad_engine.py` `_merge_times` | `abs <= Tolerance.PRECISION` (1e-6 y) | ~31.5 s | first |
| PDE 1D | `engine/pde/grid/request.py` | `is_close` (rel 1e-9, abs 0) | ~0.03 s at t=1 | first |
| MC Snowball / Phoenix | `engine/mc/{snowball,phoenix}_mc_engine.py` via `util/numerical/time_nodes.merge_time_nodes` | `abs < Tolerance.ZERO` (1e-10 y) | ~3 ms | LAST, maturity pinned |
| QUAD V2 | `engine/quad/v2/adapters.py:356` | exact unless `QuadV2Params.event_time_tolerance` (default 0.0) | 0 | first |
| Lifecycle day-snap (tracker, replay/backtest repricing, pricing surface) | `lifecycle/snapping.py` `snap_contract` | `round(t*365)/365`, per schedule; `_keep_schedule_two_last` may move a REBASED last offset by a day | whole days | kept float of the day |

The day-snap is a different, deliberate rule (the tracker observes whole closes)
and stays; but it snaps PER SCHEDULE and builds its copy with `deepcopy` +
`replace`, never `validate()`, so a cross-schedule 1-ulp pair survives it and
reaches the engines in replay.

Factory generation: `(i + 1) / n * maturity` rounds twice. Across common
tenors (0.5-3 y; monthly, quarterly, daily 252/504/378) it yields **105** pairs
that are the same calendar instant but different floats. `(i + 1) * maturity / n`
rounds once and yields **0** (it is the correctly rounded value of the exact
rational whenever `(i + 1) * maturity` is exact, i.e. for every maturity with a
short binary expansion). Copies of the double-rounding expression:
`snowball_helpers.py` lines 111 (`generate_ko_observation_dates`), 298, 416, 528,
645, 795; `phoenix_helpers.py` 205, 364; `range_accrual_helpers.py` 347, 444, 578.

Why it is more than cosmetic: the desk ruling **"a knock-out wins a tie with a
same-instant discrete knock-in"** (and KO-reset "schedule 2 in force FROM the
knock-in observation, that observation included") depends on what "same
instant" means. With KO and KI 1 ulp apart, V1/MC apply the tie rule and V2 does
not.

## 2. Goals, non-goals, anti-goals

Goals
- G1. Equal calendar instants generated by any factory are bit-identical floats.
- G2. One contract-level rule decides which numeric event times are one instant;
  every consumer (QUAD V1, QUAD V2, PDE, MC, vol-model engines, analytical
  engines, lifecycle tracker, cash legs, replay, event statistics, theta shift,
  intraday events) sees the same instants.
- G3. QUAD V2 prices the factory KO-reset at default parameters.
- G4. Times an engine combines itself (maturity, settlement, grid extras) merge
  with the same rule, through one shared function.

Non-goals
- FX products (they use their own record types, not `ObservationSchedule`) --
  follow-up once equity lands.
- Changing how dated records resolve (`ObservationRecord.resolve_time`): two
  different dates are never within the tolerance; the same date already gives the
  same float.
- Any change to pricing numerics beyond which instants exist.

Anti-goals (a failure even if it works)
- Merging genuinely distinct instants: intraday events one second apart
  (3.2e-8 y) must stay distinct.
- Silently changing V2's exact-semantics contract: V2 keeps refusing truly
  near-coincident inputs it is handed; the fix is that it is no longer handed them.
- Breaking intended equal times (TARN periods sharing a fixing date, KO-reset
  schedule 2 ending exactly at schedule 1's end, D35 equality).
- Re-certifying or refreshing anchors without the owner's sign-off.

## 3. Constraints

- House rules: `quantark.util.numerical` tolerances (no raw literals); exact
  semantics by default; no fallbacks; dated == numeric twin; every moved value
  measured and signed before landing; full suite green on the landing tree.
- `merge_time_nodes` already exists and is the W17a-sanctioned rule for MC grids
  (keep LAST of a run, `pin=` keeps maturity exact).
- Certificates record engine identities; `snowball-intraday-daily-ki-bsm` records
  `event_time_tolerance: 0.0`. The modelvalidation KO-reset builder
  (`modelvalidation/builders/equity_ko_reset.py` 181, 225, 240) calls
  `generate_ko_observation_dates`, so certified contracts can move at ulp level.
- `ObservationSchedule.resolve` is called per schedule from products AND directly
  from >15 engines/analytics (`quad_adapters`, `base_pde_solver`, barrier/sharkfin/
  accumulator MC and analytical engines, `vol_barrier_schedule`, `theta_shift`,
  `intraday/events.py`), so no single resolve call sees the whole contract.

## 4. Approaches considered

A. **Contract clock at the product (CHOSEN, owner 2026-11-23: "write the spec").**
   Layer 1: one time generator for factories. Layer 2: canonicalize the
   contract's numeric times once, at construction, across all its schedules;
   every downstream resolve reads canonical floats. Engines stop deciding
   equality for contract times; times they add themselves go through the same
   shared function. Consistent for every consumer, engine or not; V2 keeps
   exact semantics.

B. Shared engine-side helper only (every engine calls `merge_time_nodes` with one
   tolerance). Engines agree with each other, but the tracker, cash legs, replay,
   theta shift and intraday events still read raw times and can disagree with
   the engines about ties; V2's deliberate opt-in design is reversed and the
   daily-KI certificate identity moves.

C. Factory generator only. Removes the 105 factory clashes; hand-built, aged
   (REBASED) and non-factory times still reach V2 and the four engine rules stay.

## 5. Design

### 5.1 Layer 1 -- one schedule-time generator

- One public function in `quantark/asset/equity/product/option/` (name is the
  builder's), e.g. `schedule_times(maturity, num_observations, skip_first=0)`,
  computing `(i + 1) * maturity / num_observations`.
- `generate_ko_observation_dates` and all 11 inline copies listed in §1 call it.
  `generate_ko_observation_dates` keeps its signature.
- A unit test pins G1: for the tenor/frequency matrix of §1, two schedules of one
  contract that share a calendar instant share the float bit for bit, and the
  KO-reset factory pair at 11/12 is equal.

### 5.2 Layer 2 -- canonical contract clock at construction

- A shared contract-level step (one public function; my call: an explicit call,
  not a hook on `validate()`, because `snap_contract` copies never validate) runs
  wherever a priced contract is produced: product construction, `time_shift`,
  and `lifecycle/snapping.snap_contract` (AFTER its day-snap, which stays as the
  tracker's rule; replay goldens that move go to the owner). It collects every NUMERIC event
  time the contract books -- all KO/KI/coupon schedules (KO-reset: both),
  maturity, explicit numeric settlement times (`first_schedule_settlement_time`)
  -- and snaps each run of times closer than the tolerance onto one value with
  `merge_time_nodes(..., pin=maturity)`. Records keep everything else (barrier,
  payoff, rate, accrual).
- Dated records are untouched (resolved from dates at pricing time).
- Equal times stay equal; intended shared instants are unaffected.
- Two records of the SAME schedule (same kind) landing on one instant are refused
  at construction (`ValidationError` naming both times), the rule QUAD V2 already
  applies (`adapters.py`: "multiple observations of one kind share a canonical
  time"). My call: no engine may pick one record's terms silently.
- KO-reset REBASED: schedule-2 times are generated at pricing as
  `ki_time + offset` (`rebased_schedule_two_times`, MC 1168). They go through the
  same shared snap against the contract's instant set at generation.
- DCN (`dcn_schedule.py`) and every `ObservationSchedule`-bearing product (barrier,
  double barrier, one-touch, double one-touch, single/double sharkfin,
  accumulator, range accrual, snowball, Phoenix, KO-reset) are in scope; the
  builder confirms each carries numeric times through the same step.

### 5.3 Engines

- QUAD V1 `_merge_times` and PDE `grid/request.py` replace their own equality
  tests with `merge_time_nodes` at the shared tolerance for the times they
  combine themselves. Contract times arrive canonical, so their merging of
  contract times becomes a no-op; a debug assertion may check it (builder's call).
- MC already uses `merge_time_nodes`; unchanged.
- QUAD V2: semantics unchanged (default `event_time_tolerance=0.0`, the pinned
  test `test_near_coincident_dates_fail_before_large_allocation` stays). Its
  refusal message for near-coincident inputs names the two times and the
  `event_time_tolerance` knob instead of only "resource limit" (message only;
  my call -- no identity change).
- The builder inventories every other engine that builds a time set from
  resolved records (vol-model MC/PDE kernels, DCN engines, discrete QUAD,
  analytical first-observation) and routes any equality test through the shared
  function.

### 5.4 Decisions (owner, 2026-11-23: D1 + D2 confirmed, D3 = snap, D4 = (b) amendment)

- D1 Tolerance (CONFIRMED): `Tolerance.ZERO` = 1e-10 y (~3 ms): above float noise (ulp at 10 y
  ~1.8e-15), below the intraday clock's one second. Consequence: V1 stops merging
  events 1e-10..1e-6 y apart, PDE's relative rule becomes absolute.
- D2 Representative (CONFIRMED, including contract instants pinned against
  engine-added nodes): `merge_time_nodes`' rule -- the LAST member of a run, the
  maturity pinned exactly -- so MC is unchanged and V1/PDE/V2 move only where a
  run existed. Sub-question for engine-added nodes (continuous-KI grid nodes, V1
  settlement-recording nodes, PDE grid extras): under "last member" such a node
  within the tolerance AFTER a contract instant would displace it. Proposal:
  contract instants are pinned -- an engine-added node within the tolerance of a
  contract instant snaps to it. This changes MC only on such collision grids
  (W17a cases, noise-level re-draws).
- D3 SNAP (owner chose A): near-coincident numeric times are snapped silently at
  construction (today's V1/MC behaviour, made universal). Refusing was rejected:
  the day-snap deliberately keeps floats 1 ulp either side of `k/365`, so refusal
  would break replay/backtest copies and aged/hand-built contracts priced today.
  Same-schedule collisions are still refused (§5.2).
- D4 Certified contracts -- owner chose (b) AMENDMENT: probe every banked
  certificate; any anchor that moves is amended through the release procedure
  (procedure-run, the owner signs the anchors); no certified contract is exempt
  and no anchor is refreshed silently. Background: the certified KO-reset builder never passes times (it
  calls `create_ko_reset_snowball`, using `generate_ko_observation_dates` only to
  count records), and its schedule 1 / schedule 2 are built at different
  maturities and counts -- exactly the 11/12 pair -- so even legacy times would be
  snapped by Layer 2. Options: (a) exempt certified contracts (conflicts with G2);
  (b) accept the moves through a certificate amendment (procedure-run, owner signs
  anchors); (c) full re-certification.

## 6. Value impact and evidence

Expected movers, each to be MEASURED, listed (before -> after) and signed:
1. Layer 1: factory contracts with non-unit tenors (times move <=1 ulp).
   Maturity-1.0 contracts are bitwise unchanged (`*1.0` was exact).
2. Layer 2: only contracts that had a near-coincident pair.
3. Engine rule: V1 where events were 1e-10..1e-6 y apart; PDE where the relative
   rule differed from the absolute one.
4. Goldens, replay goldens, certificate anchors: probe before landing; any move
   goes to the owner, never refreshed silently. Certificates that move are
   amended (D4 (b)).

Tests that pin the intent:
- Twin: the same contract booked with 1-ulp-apart vs equal times prices
  identically (bitwise) on QUAD V1, QUAD V2, PDE and MC, with identical event
  statistics, tracker events and cash ledger.
- Tie: KO and discrete KI 1 ulp apart -> KO wins on every engine, as for equal
  times.
- Factory KO-reset prices on QUAD V2 at default params; the lobe script's
  `v2_default` arm stops refusing.
- Intraday: events one second apart stay two instants on every engine.
- Dated == numeric twin unchanged.

Release: CHANGELOG entry (Fixed + any Breaking moved values), version bump per
the release flow.
