# Performance work delivered — 2026-08-10

All six items from `FINDINGS-2026-08-10.md` are implemented. Every change is
either **bitwise output-preserving** or **opt-in**, verified by byte-comparing
full-precision outputs against a detached git worktree at the pre-change commit.

## What shipped

| # | Change | Kernel speedup | Bitwise | Commit |
|---|---|---|---|---|
| 1 | `LeverageSurface.leverage` scalar-time fast path | 1.79–1.99× | yes | `b98a8d9` |
| 2 | `solve_tridiag_batch` pivot-guard hoist | 1.17–1.52× | yes | `b98a8d9` |
| 3 | SL transport dense → sparse (n_v, 4) stencil | O(n_v²)→O(n_v) | n/a (opt-in scheme, no baseline yet) | `b98a8d9` |
| 4 | `make_df_fn` queries each distinct date once | 2000 calls → 4 | yes | `66f7b0d` |
| 5 | Optional compiled Thomas kernel | 1.75–5.81× | yes | `5a108c8` |
| 6 | Optional Numba QE variance kernel | 1.57–2.60× | yes | `365c555` |

## End-to-end

| Path | Before | After | Gain |
|---|---|---|---|
| PDE march (1y put, n_x=61, n_v=120, n_t=240, CS) | 0.442 s | **0.119 s** | **3.7×** |
| SLV MC (4 paired batches, ordinary_decayed) | 80.05 s | **57.20 s** | **1.40×** |

PDE decomposes as 1.36× from the guard hoist and a further 2.5× from the C
kernel. MC is almost entirely the leverage hoist; items 4 and 6 contribute a few
percent each, inside run-to-run noise.

## Verification

- **PDE surfaces**: 104,960 bytes byte-identical across
  {adaptive_upwind, centered} × {concentrated, uniform} × {douglas, cs}.
- **SLV MC batch deltas**: byte-identical on two cells, checked twice — once
  after the leverage/tridiag/transport commit, once after the Numba kernel.
- **QE kernel**: all eight output fields bit-identical to the NumPy reference
  across ordinary / sigma-collapse / low-Feller / zero-kappa regimes.
- **Suites**: 176 tests pass with both accelerators live, including all 28
  replay goldens. 16 tridiag tests pass with the compiled kernel absent.

The bitwise question for Numba was genuinely open, not rhetorical: NumPy 2.x
dispatches array transcendentals to SIMD implementations that need not agree
with the scalar libm calls a per-element loop makes. On this host they agree
exactly. `fastmath` stays off, since it would license reassociation.

## Accelerators are optional by construction

Neither accelerator is required, and both report which backend is live so
certification evidence can record what produced a run:

```python
from quantark.util.numerical import tridiag;  tridiag.tridiag_backend()  # "c" | "numpy"
from quantark.montecarlo import qe_kernels;   qe_kernels.qe_backend()    # "numba" | "numpy"
```

- PDE: `python -m quantark.util.numerical.build_thomas_kernel` (no dependency;
  needs only a C compiler; `-ffp-contract=off` is load-bearing for bit-identity).
  The built library is gitignored as a platform artifact.
- MC: `pip install quantark[accel]` for numba. Verified not to move numpy
  (its pin `numpy<2.5,>=1.22` already accepts the installed 2.4.6), so no
  bitwise guarantee or golden is disturbed.

## Deliberately not done

- **`np.clip` → `np.minimum` for the leverage index clips.** Equivalent and
  1.23× on that call, but worth ~42 ms of a ~36 s run (0.12%) — not enough to
  justify touching a hot numerical path.
- **Numba fusion of the whole `simulate` step body** (~38% of MC tottime). The
  QE variance slice is done; the remainder lives in a 25-argument branchy helper
  (`_advance_conditional_affine_spot`) whose faithful port is a project of its
  own, with real bitwise risk. This is the largest remaining MC lever.
- **Pre-existing circular import**: `import quantark.montecarlo` before
  `quantark.asset` raises ImportError. Reproduced at the pre-change commit, so
  it is not from this work; the engine already imported montecarlo submodules at
  module level. Worth fixing separately.

## Effect on the certification run

The savings model in `docs/mc-reference-convergence/savings.py` used pre-hoist
MC rates. At the new rate the MC-bound portion scales by ~1/1.40, so the
projected aggregate run moves from ~23 h serial / 3.8 h wall to roughly
**16 h serial / 2.7 h wall** — before counting the PDE-side 3.7×, which
shortens the per-cell refinement ladders the certification also runs.
Re-run `savings.py` with remeasured per-batch costs to confirm.
