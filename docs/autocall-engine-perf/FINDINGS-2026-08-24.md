# Autocallable engine perf findings — PDE cache-key defect, QUAD stacked event recursion

**Date:** 2026-08-24. **Code:** quantark 0.4.7rc2 (wheel), adapter
`otc_quantark_pricer_v047.py` (`qa047_settlement`). **Book:** 2026-06-30 OTC
book, 97 rows, 87 autocallables (45 部分保本雪球 / 29 非保本雪球 / 13 凤凰).
Everything below is measured on this host (arm64) through the adapter's own
build path (`build_trade_state` per row, `greek-bump/v1` cells, 7 solves per
row: base + spot_up/down + vol_up + rate_up + div_up + theta).

## Full-book wall time (8 workers, sequential runs, all 97 ok / 0 error)

| Engine | Config | Wall | Per-cell solve cost implied |
|---|---|---|---|
| MC | 100k paths, QMC (Sobol) | **230 s** | ~1.6 s |
| PDE | standard accuracy, grid 400×200 base | 540 s | ~5.1 s |
| QUAD | gridXQuad 1001 | 924 s | ~6.3–6.9 s |

Cross-engine consistency on the same book: max |PV diff| over the 87
autocallable rows is 4.8 bp of notional (MC vs PDE) and 2.7 bp (QUAD vs PDE) —
the engines agree; only their costs differ.

## Issue 1 — PDE: per-time-step cache-key reconstruction (>90% of solve time)

A 1.9y snowball PDE solve takes ~5.5 s wall (16.75 s under cProfile). The
profile shows the time-stepping loop paying a pure-Python serialization tax
every step:

```
_time_stepping_two_surface                    15.37s  (1,868 steps)
 └ _set_boundary_conditions_v0   ×1868        15.22s
    └ _get_ko_payoff_at_time     ×1868        15.21s
       └ _get_cached_ko_records  ×1853        15.11s
          └ _observation_cache_key ×1853      14.85s
             └ _product_cache_token
                ├ _freeze_cache_value  29.3M calls   7.9s
                └ SnowballOption.cache_key()         6.9s
_build_grids (once)                              1.35s
tridiagonal algebra                              ~noise
```

`quantark/asset/equity/engine/pde/snowball_pde_solver.py:3139`
(`_get_cached_ko_records`, same pattern at `:3156` `_get_cached_ki_profile`)
builds its OrderedDict key via `_observation_cache_key` →
`base_pde_solver.py:742` `_product_cache_token` → `SnowballOption.cache_key()`
(`snowball_option.py:1202`), which re-serializes the entire product — every
KO/KI schedule record — then `_freeze_cache_value` deep-freezes and sorts it.
~8 ms per call × 1,853 calls ≈ 15 s. The KO/KI records are a function of
(product, env) only and are invariant for the whole solve; the `OrderedDict`
hit itself is instant. The cache works; the key construction is the cost.

**Fix candidates (no numerical impact — records are solve-invariant):**

1. Hoist `_get_cached_ko_records` / `_get_cached_ki_profile` out of the
   time-stepping loop: resolve once before stepping, pass down.
2. Memoize `_observation_cache_key` per solve on the solver instance
   (id-keyed; precedent: the `"strict"` strategy already keys on
   `id(product)`).
3. Memoize `SnowballOption.cache_key()` on the product — helps every engine's
   cache path, not just this solver.

Expected effect: snowball PDE solve ~5.5 s → ~0.3–0.6 s (grids + algebra
only); full-book PDE run plausibly 540 s → ~1–2 min, restoring the expected
PDE < MC ordering.

## Issue 2 — QUAD: stacked KO-indicator event recursion re-run in every greek cell

Plain `price()` on the same snowball row:

| Engine | `price()` | `price_with_events()` (= what each greek cell pays) |
|---|---|---|
| QUAD | **0.54 s** | **6.8 s** (12.6×) |
| MC | 1.62 s | 1.6 s |
| PDE | 5.5 s | 5.1 s |

The execution framework's `greek-value/v1` runner
(`quantark/execution/greeks.py:263` `run_greek_bump`) prices cash-leg rows via
`price_with_events(..., streams=...)` in **every one of the 7 bump cells**,
because leg PVs are valued off the event distribution per cell.

- MC: the event distribution is a byproduct of the simulated paths → free.
- PDE: solvers honor `streams` column pruning; event columns ride inside the
  single backward solve → ~free (`base_engine.py:151` docstring names the PDE
  autocallable solvers as the pruning supporters).
- QUAD: `SnowballQuadEngine.calculate_event_stats`
  (`quad/snowball_quad_engine.py:549`) runs a **second quadrature recursion
  with one indicator surface stacked per KO observation date**
  (`:743-747`, `n_rows = n_ko + extras`). For a monthly-obs snowball that is
  ~24 surfaces × the 1001-point grid convolutions — hence 12.6× the plain
  price pass — and it ignores `streams`, so the full stack is recomputed in
  all 7 cells of every row.

**Fix candidates:**

1. Honor `streams` pruning in the QUAD event-stats recursion (skip indicator
   rows whose events no requested stream needs).
2. Cache the base event distribution across a row's bump cells (KO dates do
   not move under spot/vol/rate/div bumps; only the diffusion does — needs a
   correctness argument per bump type before trusting it).
3. Fuse the price pass and the stats pass so a cell pays one recursion, not
   two.

## All-rows per-cell distribution (87 autocallable rows, serial probe, one warm
`price_with_events` per row per engine — the exact per-cell solve)

| Engine | median | mean | max | 7 cells × Σ(cell), serial |
|---|---|---|---|---|
| MC | 1.51 s | 1.42 s | 4.25 s | 867 s |
| PDE | 4.27 s | 5.51 s | 12.63 s | 3,357 s |
| QUAD | 6.17 s | 8.16 s | **42.5 s** | 4,968 s |

Dividing the serial estimates by 8 workers (108 s / 420 s / 621 s) tracks the
observed full-book walls (230 s / 540 s / 924 s) once the 10 analytical rows,
per-cell `build_trade_state` (~0.06 s) and session overhead are added — the
per-cell event-distribution solve is the dominant term for all three engines.

Distribution shape:

- PDE cost scales with maturity × time-step density (worst rows 2.9–3.0y
  部分保本雪球, 12.5 s/cell) — consistent with the per-step cache-key tax of
  Issue 1 growing with step count.
- QUAD's worst row by far is a 2.98y **部分保本凤凰** at 42.5 s/cell — Phoenix
  stacks extra coupon-trigger indicator rows on top of the KO rows
  (`_n_extra_quad_rows` override), compounding Issue 2.
- MC is flat (1.4–2.8 s) because path count, not schedule length, drives its
  cost; events ride the paths for free.
