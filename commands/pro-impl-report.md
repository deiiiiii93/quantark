# /pro-impl-report

Create a professional implementation report with a Methods/Results/Discussion layout.

## When to use
- The user asks for a professional report on implementation work.
- The user requests a Methods/Results/Discussion structure.
- The user invokes `/pro-impl-report`.

## Inputs to confirm (ask only if missing)
- Target output path (default: `IMPLEMENTATION_REPORT.md` in repo root)
- Scope (which features/modules/products to cover)
- Any required benchmark or validation data to include

## Output format (template)
Use this outline, keeping explanations accessible:

1. Title and metadata
2. Abstract
3. Methods
   - Product/setting
   - Numerical approach or implementation steps
4. Results
   - Key outcomes and quantified impacts
5. Discussion
   - Why the changes help
   - Limitations / next steps
6. Practical guidance (recommended settings)
7. Files updated

## Style
- Professional report tone
- Plain language explanations for theory
- Avoid heavy jargon without a short explanation
- Use ASCII only unless the file already contains Unicode
